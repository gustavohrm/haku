# Agent instructions: `tauri/`

## Traps

- A webview is created but never navigates, with no error anywhere, when the command driving it is synchronous. Tauri runs synchronous commands on the main thread, and creating, moving or raising a webview dispatches to that same thread and waits, deadlocking the event loop. Prefer an `async` command for anything that drives a webview. [Architecture § Threading](../docs/architecture.md#threading) records the rule. Held on Tauri 2.
- The browser believes restored tabs are already loaded when session restore goes through open or select. Those return effects meant for real webviews; at startup there are none, so the effects are discarded while the state records them as applied. Prefer `Browser::restored`.
- A tab returns to an older page after a single-page-app route change when the URL is taken from a page-load hook alone, because route changes fire no load. Content webviews have no IPC, so the page cannot report it either. Prefer `platform::observe_page`, which [Page observation](../docs/specs/page-observation.md) describes. Granting remote pages IPC is a security decision, not a fix for this.
- A content webview can lose its first navigation commit when it is created directly on its URL. Prefer creating the slot on `about:blank`, observing it, then navigating it, as `webview/` does.
- A capability scoped with `"windows": [...]` grants its permissions to every webview in those windows, and content webviews are children of them. Prefer scoping by `webviews` only, by the chrome's `window-*` label. [Architecture § Security](../docs/architecture.md#security) records why.
- `pnpm tauri build` fails while every debug check passes when Tauri's `devtools` feature is dropped, because `open_devtools` exists in a release build only through it. `pnpm check:release`, which CI runs, catches it with `no method named open_devtools`. Held on Tauri 2.
- specta refuses to export a 64-bit integer and maps a bare `f64` to `number | null`. Prefer `#[specta(type = specta_typescript::Number)]` on numbers that cross the IPC boundary. Held on specta 2.0.0-rc.25 and specta-typescript 0.0.12.
- Haku crashes with `STATUS_ACCESS_VIOLATION` when an `ICoreWebView2FrameInfoCollectionIterator` is used after its collection is released, as in `info.AssociatedFrameInfos()?.GetIterator()?`. The iterator does not hold its collection. Prefer binding the collection to a variable that outlives the loop, as `platform::windows_impl::read_process_infos` does. Held on webview2-com 0.38.2 with the WebView2 runtime current on 2026-10-06.
- WebView2 refuses a webview as a page's new window, and the tab it opens in loses `window.opener`, when the webview has loaded anything, including a parked slot's `about:blank`. A Tauri webview created on `about:blank` qualifies only because Tauri skips that initial navigation (`tauri-runtime-wry`, `if url != "about:blank"`). Prefer a slot from `Browser::bind_new`, created by `webview::create_slot` and handed over before anything navigates it. Held on Tauri 2.10.3 and wry 0.54.4.
- An initialization script does not run in a page opened with `window.open` when the page has the opener's origin, as an extension page opening another does. The new page reuses the window object of the initial `about:blank` document, and the script ran there already. Prefer `noopener`, as the extension page script's `windows.create` does. Held on WebView2 155.0.4283.62.
- An extension page goes blank when it calls `chrome.windows.update` with a size or position: the engine moves its webview within Haku's window. Prefer stripping them, as `inject::extension_page_script` does. Held on WebView2 155.0.4283.62.
- `chrome.tabs.getCurrent()` in a page shown in its own webview answers with that webview's tab, a toolbar popup's included, where Chrome answers with nothing. Prefer the extension page script for a popup, which answers as Chrome does. Held on WebView2 155.0.4283.62.
- A window created right after one with the same label is destroyed fails with "a webview with label … already exists", because destroying is not finished when the call returns. Prefer a new label each time, as `webview::open_extension_popup` does. Held on Tauri 2.10.3.
- A webview window reports `WindowEvent::Focused` for its page's focus, not the window's: one shown and given focus with `set_focus` reports nothing, and so never reports losing it, until its page is focused, and a hidden one being created reports focus and losing it. Prefer focusing the webview as well, and ignoring focus events while hidden, as the toolbar popup does. Held on Tauri 2.10.3 with WebView2 155.0.4283.62.
- Haku crashes with `STATUS_ACCESS_VIOLATION` when a webview is destroyed while a new-window request it made is still being answered. Bitwarden's pop-out button did it: the window it asked for took focus, so the toolbar popup closed for losing focus before the request was answered. A click sent through the DevTools protocol does not give the page focus, so it does not reproduce it; a real click does. Prefer leaving the close to the answer while a request is pending, as `POPUP_REQUESTS` in `ipc/commands.rs` does. Held on Tauri 2.10.3 with WebView2 155.0.4283.62.
- The next launch shows no window content, with no error, after Haku is force-killed. Its WebView2 processes outlive it for a while and hold the profile. Prefer waiting for the `msedgewebview2.exe` processes started with `--webview-exe-name=haku.exe` to exit before launching again. Held on WebView2 for Windows.
